Performance

TensorRT uses Optimized Fast decoding automatically. If it fails, saved latents retry with the internal Stable decoder.

SageAttention 2 is preferred. Performance reports record the kernels actually used, including fallbacks.

Avoids reloading decoded batches. Raw recovery files are still saved. TensorRT only; falls back to the Stable path if it fails.

Reuses one model selection between previews/chunks. Frees model VRAM before decoding and releases the CPU cache after 5 idle minutes. Requires enough free system RAM.

Conservatively detects hard cuts and skips cross-shot color/noise matching. Off by default; flashes and similarly colored shots can be ambiguous.

Export quality

New presets apply to TensorRT renders and post-only reprocessing. NVENC is tested before export; unavailable hardware falls back to a software encoder with the same codec family and bit depth. Quality values are not equivalent between encoders.

10-bit SDR keeps floating-point precision until RGB48 conversion; it is not HDR. HEVC/AV1 may need an external player. H.264 remains the compatibility default.

Post-processing

Uses the proven Color + noise match treatment over 2 frames at every decoded batch boundary.

Warning: disabling seam smoothing can cause visible noise, color, or texture changes every temporal batch—for example, every 21 frames.

Skin finishing

Restart SeedVR Studio to enable skin finishing. Refreshing the page alone cannot update the Python processing backend.

Off by default. Uses a stabilized skin mask and protects strong facial contours. Blemish cleanup can still affect permanent marks; preview first.

Render engines

SeedVR2 + TensorRT runs the SeedVR2 restoration pipeline with the TensorRT-accelerated VAE decoding path. It is the recommended fast option on supported NVIDIA systems.

SeedVR2 (Legacy) uses the standard SeedVR2 PyTorch path. It can support more temporal batch sizes, but it is substantially slower and may take a very long time on video. Use it at your own risk for long renders.

TensorRT currently supports temporal batches 5 and 21. The batch dropdown updates automatically when you switch engines.

Resumable long-video rendering

When enabled, the full video is divided into manageable chunks and processed one at a time. Completed chunks are saved immediately, with a small temporal overlap to reduce boundary seams.

If a render fails, the completed chunks remain on disk. The failure reason and backend log are saved, and Retry from last chunk continues from the first unfinished chunk automatically.

Auto (recommended) uses the video duration, frame rate/frame count, and temporal batch size to target roughly ten useful checkpoints, then selects the closest available chunk length. The chosen value is saved in the job manifest and render log.

This feature is off by default. It does not change the normal render quality or require any manual chunk assembly.
